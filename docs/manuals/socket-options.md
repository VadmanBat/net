# ⚙️ Параметры настройки сокета

Справочник полей `SocketOptions` и пресетов `SocketPreset`.  
Пустое поле (`std::optional` без значения) означает: **не менять** настройку ОС.

Заголовок: `include/net/socket/socket-options.h`  
Применение: после `connect` / на accepted peer — `setOptions(...)`.

---

## Параметры

| Параметр             | Смысл                                                                                                            | Цель                                                                                                  | Типичные значения                                                                                       |
|----------------------|------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| **no_delay**         | Отключает алгоритм Nagle: мелкие порции данных уходят в сеть сразу, без ожидания «склеивания».                   | Снижает задержку для чата, команд, частых коротких сообщений.                                         | `true` — быстрее отклик; `false` / не задано — решение ОС (может чуть буферизовать).                    |
| **keep_alive**       | Периодические проверки «живо ли соединение», если долго нет трафика.                                             | Заметить обрыв линии, когда никто ничего не шлёт. Срабатывает **не мгновенно** (минуты на многих ОС). | `true` — для долгих сессий; не заменяет таймаут на приём.                                               |
| **send_buffer_size** | Размер **отправного** буфера ядра (байты): сколько данных ОС может принять от приложения, пока сеть их забирает. | Крупные передачи: меньше простоев, если приложение шлёт быстрее, чем уходит в канал.                  | `256 * 1024` … `1 << 20` (1024 МиБ). ОС может округлить размер. `0` в setSendBufferSize не принимается. |
| **recv_buffer_size** | Размер **приёмного** буфера ядра: сколько входящих данных ОС копит, пока вы не вызвали `receive`.                | Крупный поток: меньше потерь/тормозов, если приложение читает с паузами.                              | Аналогично send, часто зеркально.                                                                       |
| **send_timeout_sec** | Сколько **секунд** ждать, если `send` не может сразу отдать данные в буфер ядра.                                 | Чтобы программа не зависла навечно на отправке.                                                       | `10`–`30` для интерактива; `60`–`120` для файлов. `0` — очень короткий/нулевой таймаут (зависит от ОС). |
| **recv_timeout_sec** | Сколько **секунд** ждать данных при `receive`.                                                                   | Чтобы не ждать входящие данные бесконечно.                                                            | То же; для «иногда тишина» берите с запасом или смотрите keep_alive.                                    |

### Важно про таймауты

Если в `SocketOptions` задан **хотя бы один** из `send_timeout_sec` / `recv_timeout_sec`, библиотека выставляет **оба
** (незаданный копируется из заданного). Нельзя через один optional «поменять только send, не трогая recv».

Таймауты — **локальные** для этого сокета; у клиента и сервера они могут отличаться.

## Пресеты (`SocketPreset`)

Готовые наборы. Не заполняют «все» поля — только типичные для задачи.

| Пресет          | Задача                          | Что выставляет                                             |
|-----------------|---------------------------------|------------------------------------------------------------|
| **Interactive** | Чат, команды, короткий обмен    | `no_delay = true`, таймауты **10** с                       |
| **Bulk**        | Файлы, большие куски данных     | `no_delay = true`, таймауты **120** с, буферы **1024 МиБ** |
| **LongLived**   | Долгое соединение, бывают паузы | `keep_alive = true`, таймауты **60** с                     |

```text
make_socket_options(preset)  →  SocketOptions
socket.setOptions(preset)    →  то же, сразу применить
```

Пресет можно взять и **доработать** вручную (изменить/добавить поля структуры).

---

## ServerOptions (кратко)

| Поле              | Смысл                                                                                      |
|-------------------|--------------------------------------------------------------------------------------------|
| **reuse_address** | Упрощает повторный `listen` на том же порту после перезапуска (`true` по умолчанию).       |
| **accepted**      | `SocketOptions` (или результат пресета), применяемые к **каждому** клиенту после `accept`. |

Серверу пресеты задают так: `opts.accepted = make_socket_options(SocketPreset::Interactive)`.

## Готовые фрагменты

### Пресет на клиенте

```cpp
#include <net/tcp-socket.h>

net::TcpSocket sock;
if (!sock.connect("127.0.0.1", 50235))
    return;

sock.setOptions(net::SocketPreset::Interactive);
// sock.setOptions(net::SocketPreset::Bulk);
// sock.setOptions(net::SocketPreset::LongLived);
```

### Свой набор полей

```cpp
net::SocketOptions opts;
opts.no_delay         = true;
opts.send_timeout_sec = 30;
opts.recv_timeout_sec = 30;
opts.send_buffer_size = 256 * 1024;
opts.recv_buffer_size = 256 * 1024;
sock.setOptions(opts);
```

### Пресет + правка

```cpp
net::SocketOptions opts = net::make_socket_options(net::SocketPreset::Bulk);
opts.recv_timeout_sec = 300; // дольше ждать приём
sock.setOptions(opts);
```

### Сервер: пресет для всех peer’ов

```cpp
#include <net/tcp-server.h>

net::ServerOptions server_opts;
server_opts.reuse_address = true;
server_opts.accepted      = net::make_socket_options(net::SocketPreset::Bulk);

net::TcpServer server;
server.setOptions(server_opts);
server.listen("0.0.0.0", 50235);
```
